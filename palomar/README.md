# Rational quivers: Comparator project for the Palomar registry

This directory is a Lake project of its own. It states Theorem B of

> Fabian Januszewski, *Rational structures on quivers and a generalization of Gelfand's equivalence*,
> arXiv:2506.23251.

as a Comparator challenge and proves it from the Lean formalization in `../lean`, which it
requires as a path dependency within this repository. It lives on the branch `palomar` of
[drjanosch42/rational_quivers](https://github.com/drjanosch42/rational_quivers), whose `lean/` is that
of tag `v1.1.0` (commit `23dabdf6f900d12f9ed926ef4602ff637c68dcf5`, Zenodo concept DOI
10.5281/zenodo.23735853). That version ports `v1.0.0` (commit `b69c173…`, Zenodo DOI
10.5281/zenodo.23735854, the version that the paper cites) to Lean `v4.35.0`, Mathlib `v4.35.0` and
the Lean module system, which Palomar requires. Its mathematics and statements are those of
`v1.0.0`; the port's changes are summarized in `formalization.yaml` (`related_formalizations`,
`fidelity.divergences`).

## What is compared

`comparator.json` compares two theorems of `Challenge.lean`:

* `RQStatement.Palomar.theoremB` (Theorem B of the paper). Let `E` be a field of characteristic 0, let
  `L_E = E(√-1)` and let `ℓ ≥ 0`. Then the category `HC ℓ E D` of `E`-rational Harish-Chandra modules
  for `(𝔰𝔩₂, SO(2))` with generalized infinitesimal character `ℓ²` is equivalent to the category
  `Rep^nil(Γ_E)`. Its objects are the finite-dimensional nilpotent representations of the `E`-rational
  quiver `Γ_E`. For `ℓ ≥ 1` this is the Gelfand quiver, whose objects must also satisfy
  `a₋b₋ = a₊b₊`. For `ℓ = 0` it is the cyclic quiver.
* `RQStatement.Palomar.imagUnit_nonempty`. The datum `L_E = E(√-1)` exists for every field `E`, so the
  statement is not vacuous.

`Challenge.lean` imports only Mathlib. It restates every definition the two statements use (about
500 lines of definitions) as a copy of the formalization's definitions, in the namespace `RQStatement`.

## How the Solution proves it

* `RQPalomar/Statement.lean` is a byte-identical copy of the definitions block of `Challenge.lean`
  (`scripts/check-statement-copy.sh`), compiled against the same imports. Its constants are therefore
  the Challenge's constants.
* `RQPalomar/Bridge.lean` maps the copies to the formalization's definitions and back:
  * `HC ℓ E D ≌ RationalQuivers.HC.HC ℓ E D'`;
  * an equivalence of the categories of representations of the rational quivers;
  * `Γ_E` equals `RationalQuivers.Gelfand.GammaE`;
  * nilpotence and the Gelfand relation correspond.

  These are equivalences of categories proved in Lean. They lose no information.
* `Solution.lean` composes the bridge with `RationalQuivers.Gelfand.gelfand_equivalence`.

## Fidelity

The paper and the formalization state that the paper's explicit functor `𝔼_E` is an equivalence
(`∃ e, e.functor = E_E E D ℓ`). The compared statement says only that an equivalence exists. Restating
`𝔼_E` would put several thousand lines of construction into the Challenge, which is not allowed. The
other modelling choices are listed in the docstrings and in `formalization.yaml`
(`status.scope`, `fidelity.divergences`):

* Harish-Chandra modules over `E` are given by Galois descent from `L_E`.
* The central character is stated in its parity form.
* `L_E` is an abstract field generated by `√-1`.
* Everything lives in universe 0.

## Registry entry

Submissions to the Palomar registry go through https://submit.palomar-registry.org/. The entry uses
the repository `drjanosch42/rational_quivers` at a commit of this branch, with project path `palomar`,
Comparator configuration `palomar/comparator.json` and metadata `palomar/formalization.yaml` (the
default for that project path). All paths are relative to the repository root.

## Checking it locally

Requirements: `elan`, `bubblewrap` (`bwrap`), `python3`. From this directory:

```
lake exe cache get          # Mathlib only; RationalQuivers (../lean) is built from source
lake build                  # Challenge, RQPalomar, Solution
bash scripts/check-statement-copy.sh
python3 scripts/check-lean-sources.py
ruby scripts/validate-formalization.rb
./scripts/verify-comparator.sh              # the toolchain's `lake comparator`, as Palomar runs it
./scripts/verify-comparator.sh --paranoid   # additionally all of the toolchain's checkers
```

The scripts come from [PalomarTemplate](https://github.com/PalomarRegistry/PalomarTemplate)
(Apache-2.0). `scripts/validate-formalization.rb` is unchanged. `scripts/check-lean-sources.py`
scans the whole repository rather than this directory, as Palomar does.
`scripts/verify-comparator.sh` builds the Challenge and the Solution and exports them with the
toolchain's `leanexport` before `lake comparator` judges the two exports, as Palomar's verifier
does: the sandbox of a plain `lake comparator` binds only this directory and cannot see `../lean`.
`scripts/check-statement-copy.sh` belongs to this project.

The workflow `.github/workflows/palomar-preflight.yml` runs Palomar's own reusable verifier
(PalomarSubmission, pinned to a commit) in `full` mode on every push to the branch `palomar`.
